# GRAIN platform baseline

## Platform capabilities

- **Safari and iOS.** Safari 27.2 is the stable 27.x reference checked here. Safari 26.6 is a compatibility target. Use `display: standalone` and detect the actual display mode with `matchMedia("(display-mode: standalone)")` plus `navigator.standalone === true` as an iOS fallback. On iPhone and iPad, guide the user through Share → Add to Home Screen and Open as Web App where offered. Show install help on demand. In standalone, retain an in-app Back action with a parent fallback for deep links. [Safari 26.6](https://developer.apple.com/documentation/safari-release-notes/safari-26_6-release-notes) · [Safari 27.2](https://developer.apple.com/documentation/safari-release-notes/safari-27_2-release-notes) · [Safari 26 Home Screen behavior](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)
- **iOS capabilities.** Web Push and badging are available to eligible Home Screen web apps. Check push, service worker, and permission availability, and request notification permission from a deliberate user action. Catch badging failures and retain the in-app unread count. The EU retained Home Screen web apps. Use the same browser-tab and in-app notification fallbacks wherever install or push is unavailable, restricted, or denied. [WebKit Push and Badging](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) · [European Commission DMA Q&A](https://digital-markets-act.ec.europa.eu/citizens-and-whistleblower-portal/eu-citizens-qa_en)
- **WebKit enhancements.** Offer WebAuthn passkeys in secure contexts with server-side ceremony verification and a usable alternate sign-in or recovery path. Gate same-document View Transitions on `document.startViewTransition` and skip them with reduced motion. Verify cross-document support separately. Gate Anchor Positioning on each CSS feature used and retain normal layout or a simple positioned fallback. Use `100dvh` and safe-area environment variables with fallbacks. [Safari 18 WebKit features](https://webkit.org/blog/15865/webkit-features-in-safari-18-0/) · [Safari 26 WebKit features](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/) · [Apple passkeys](https://developer.apple.com/passkeys/)
- **Chromium.** Chrome 158 is the stable reference checked for Android and desktop. A Chrome 159 Android early rollout is tracked separately. Provide a stable manifest `id`, `start_url`, `scope`, `display`, `name`, `short_name`, `description`, and screenshots appropriate to the form factor. Supply regular 192×192 and 512×512 icons and a separate 512×512 maskable icon. Offer a custom install button only when a prompt event is captured. Retain normal browser-menu guidance. [Chrome Releases](https://chromereleases.googleblog.com/2026/11/) · [Richer Install](https://developer.chrome.com/blog/richer-pwa-installation)
- **Optional integrations.** Use `scope_extensions` only with verified associations for each extra origin. Keep independent routing, storage, and service worker scope per origin. Gate `protocol_handlers`, `share_target`, and `file_handlers` by supported OS, browser, and installation context. Test actual registered launches. Maintain ordinary routes, paste/upload alternatives, and a file picker. Check `navigator.canShare` when available and handle share cancellation or failure. [Scope Extensions](https://developer.chrome.com/docs/capabilities/scope-extensions) · [Share Target](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target/) · [File Handling](https://developer.chrome.com/docs/capabilities/web-apis/file-handling) · [Protocol Handling](https://developer.chrome.com/docs/web-platform/best-practices/url-protocol-handler)

## Layout and typography

- Use one navigation landmark with bottom tabs below 600 CSS px, a rail from 600 through widths below 840, and a persistent sidebar at 840 and above. Limit primary destinations to five with visible labels. Use a split pane only where both panes fit and the workflow benefits. Collapse ancillary panes in short windows when needed. These width classes apply to the three-region PWA composition. GRAIN’s workspace shell uses its existing container breakpoints. [Android window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)
- Use a locked dynamic-height shell only on app routes, with safe-area padding and explicit inner scroll regions. Document and content routes may use normal page scrolling. Keep focused controls above the keyboard and restore full geometry when it closes. Support zoom and reflow at 320 CSS px, with horizontal scrolling reserved for intrinsically wide content or bounded navigation. Preserve the current route and edits across iPhone Duo outer/inner display changes and Android folding. Treat viewport segments as optional enhancement after verifying support and geometry. Keep tap targets and text off any detected hinge. [Apple layout](https://developer.apple.com/design/human-interface-guidelines/layout) · [Designing for iPhone Duo](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo)
- Use GRAIN’s theme typography and preserve its grade-as-signal font. Use a system stack for unthemed native UI and rem-based text with bounded fluid scaling, 1rem minimum for body and form text, and at least 1.5 body line height. Test 200% text enlargement. Require 4.5:1 normal text contrast, 3:1 for large text and essential controls and focus cues. Validate the rendered contrast over translucent surfaces. [Apple accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

## Touch, materials, and motion

- Align spacing to a 4 CSS px grid and make PWA touch controls at least 44×44 CSS px. GRAIN’s general control minimum remains governed by the existing component contract. Preserve selectability on content and inputs. Suppress system tap highlight and selection on custom UI chrome only when equivalent pressed and focus feedback is present.
- Use fast compositor-friendly press feedback around scale 0.98 with reduced-motion overrides. Contain vertical overscroll only in intended app scrollers. Preserve native scroll physics, and offer a visible keyboard-operable alternative to every custom gesture.
- Pair translucent material with a fully opaque fallback. Honor light/dark, reduced transparency where exposed, forced colors, and reduced motion. Use the existing GRAIN theme aliases. The reference token layer defines PWA sizing, motion, and material values in terms of those aliases. DTCG 2025.10 defines the exchange format, while CSS custom properties are its web-facing representation. [Apple materials](https://developer.apple.com/design/human-interface-guidelines/materials) · [Material 3 color roles](https://m3.material.io/styles/color/the-color-system/) · [DTCG Format](https://www.designtokens.org/tr/2025.10/format/)

## Offline and storage

- Treat IndexedDB and Cache Storage as evictable. WebKit's seven-day ITP rule concerns browser use and qualifying interaction, with an installed first-party exemption. Modern quotas are contextual and may be disk-relative. GRAIN's initial budget is at most 5 MiB of uncompressed core shell assets, with separate bounded budgets for disposable content. [WebKit ITP](https://webkit.org/tracking-prevention/) · [WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/)
- On reachable launches, verify the active version's shell cache and repair missing assets. Deduplicate repairs and stage a full new version before switching. Keep the previous working shell if repair or update fails and prune obsolete caches once old clients are done. Re-register a missing worker on a reachable launch. If both shell and worker have been evicted, first offline navigation may require the network to recover.
- Use `navigator.storage.estimate()` where available as a signal. Handle denied storage, `QuotaExceededError`, and missing stores. Reclaim disposable data first and keep server-acknowledged data recoverable. For offline edits, use idempotent operations and a bounded persistent queue where available, show unsynced status, retry on return and restore after reload when possible. Provide an export for unsynced work when durability is uncertain. Test first load offline, warm offline, partial update, lost storage, and reconnection.
